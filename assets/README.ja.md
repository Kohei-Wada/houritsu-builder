# houritsu

[English](README.md)

日本のすべての法令を git の履歴にしたリポジトリ。1つのコミットが、1つの改正法令の施行に
あたる。`git log laws/act/415/415AC0000000057.md` は個人情報の保護に関する法律の改正履歴で、
`git show <commit>` は1つの改正が変えた箇所である。

git を使わない人は [git を使わない人向けのガイド](https://qiita.com/program3152019/items/bbacbb1c281bc698fd80) を参照。

> **コミットの SHA は安定しない。** 履歴は e-Gov のデータから作り直し、force-push する。
> 法令は、パス、施行日、改正法令の番号で参照すること。[制約](#制約) を参照。

## 構成

- `laws/<法令種別>/<法令IDの先頭3文字>/<e-Gov の法令ID>.md`。メタデータは YAML
  フロントマターにある。先頭3文字は公布の元号と年である（`415` = 平成15年）。
- 表は HTML にしている（結合セルを保つため）。図と様式は e-Gov にある添付ファイルへの
  リンクで、独立した行に置く。文中や表のセル内では HTML のリンクにする。図の約3割は
  e-Gov に添付がなく、代わりに `（図：e-Gov に画像なし）` と表示する。
- 目次は省いている。見出しの繰り返しにすぎないためである。
- `main`：施行済みの版。`upcoming`：公布済みで未施行の版。
- コミットの日付 = 施行日（日本時間 00:00）。トレーラーは `Amendment-Law-Id` と `Enforced`。
  改正法令が法律のときは、`Bill`（国会の議案）、`Bill-Submitter`（提出者。例：`内閣`、
  `神谷宗幣君外四名`）、`Bill-Url`（衆議院のサイトにある議案の本文。議案の理由もそこにある）
  も付く。`Skipped-Revision` は e-Gov に本文がない版を示す。そのコミットの差分は、その版の
  変更も含む。
  git は1970年より前の日付を記録できないため、それより前の日付は 1970-01-02 として記録する。
  実際の日付は `Enforced` トレーラーとフロントマターにある。
- 施行日がまだ決まっていない改正は、`enforced: "undetermined"` と `Enforced: undetermined`
  を持ち、`upcoming` の最後のコミットになる（日付は e-Gov が仮に使う 2117-12-31）。
  フロントマターの `enforcement_comment` は、施行日を改正法令の文言のまま示す
  （例：政令で定める日）。これがあるとき、`upcoming` の日付は e-Gov の見込みである。
- 廃止された法令のファイルは、廃止する法令のコミットで削除される。その履歴は
  `git log -- <file>` に残る。

## 制約

- **履歴は制定時からではなく、2015年頃から始まる。** e-Gov の改正履歴データは2015年頃から
  増える（それより前は年に数百コミット、2019年からは年に約2千コミット）。そのため、
  コミットの日付の時系列は、立法の量だけでなく e-Gov の収録範囲も表している。
- **`git blame` が示すのは収録の時期で、文言ができた時期ではない。** 法令の最も古いコミットは、
  収録が始まる前からあった行をすべて含む。刑法の大半は2016年のコミットのものと表示される。
  「その時点ですでにあった」と読むこと。
- **履歴が少ない法令が多い。** 法令の約3分の1は、コミットが1つしかない。
- **法令は、e-Gov にある最も古い版から現れる。** e-Gov が後の版しか収録していない法令は、
  古い日付をチェックアウトしてもファイルがない。古い条文が出てくるわけではない。
  2010-01-01 の時点では約2,800法令、現在は9,000法令である。
- **コミットの SHA は安定しない。今後も安定させない。** houritsu は e-Gov のデータから
  作るものであり、追記だけで伸びる記録ではない。ビルドのたびに履歴全体を作り直す。SHA が
  変わるのは、e-Gov が過去の版を訂正したとき、遅れて届いたデータが履歴の途中に入ったとき
  （コミットは施行日の順に並ぶ）、レンダラーの修正でファイルが変わったときである。1つの変更で、
  それより後の SHA がすべて変わる。そのため、GitHub の SHA 付きパーマリンクは切れることがある。
  法令は、ファイルのパス（法令ID）、施行日、改正法令の番号で参照すること。これらは作り直しても
  変わらない。ただし `upcoming` では、未定または見込みの施行日が、確定したときに変わる。
  これらは各コミットのメッセージ（`施行日`、`改正法令`）とフロントマター
  （`amendment.enforced`、`amendment.law_num`）にある。フロントマターの `revision_id` は
  e-Gov がその版に付けた ID で、同じ3つを1つの項目に持つ：
  `<法令ID>_<施行日>_<改正法令のID>`。e-Gov の ID が改正法令を示さない版では、改正法令の ID が
  0 の並びになる。保存するキーにはこれを使うこと。

## 法令を探す

ファイル名は e-Gov の法令IDで、題名が変わっても変わらない。題名で探すには、フロントマターを
検索する。

```sh
git grep -l '^title: "個人情報の保護に関する法律"' -- laws
```

## 1つの条を追う

見出しの深さは、条の前後にある章の構成で変わる。そのため、どの深さにも一致させる。

```sh
git log -L '/^##*  *第十六条/,/^##*  *第十七条/:laws/act/415/415AC0000000057.md'
```

これは最初に一致した箇所、つまり本則を対象にする。附則の条を追うには、範囲の始点を
その附則の見出しにする。見出しは改正法令を示している：`/^## 附　則（令和二年/,/^## 附　則/`。

## 出典

この節は、データの出典と加工の内容を示すものである。次の節のライセンス条件とは別である。

出典：e-Gov法令検索（<https://laws.e-gov.go.jp/>）、PDL1.0（<https://www.digital.go.jp/resources/open_data/public_data_license_v1.0>）

e-Gov法令検索の法令データ（法令API v2）を [houritsu-builder](https://github.com/Kohei-Wada/houritsu-builder)（Kohei-Wada）が markdown に加工して作成。
条文の文字は変更していない（markdown のための見出し記号とエスケープ、図へのリンクを加えた）。正本は官報。改正履歴は e-Gov が提供する範囲に限る。

議案との対応：[衆議院議案データベース](https://github.com/smartnews-smri/house-of-representatives)（smartnews-smri、MIT）。議案番号と本文ページへのリンクのみ使用。

## ライセンス

法令の条文は著作権の対象ではない（著作権法第13条）。条文を機械的に markdown へ変換したものも
同じである。これらは許諾なしに利用できる。CC BY 4.0 は、その利用に制限を加えない。

[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) は、このリポジトリのうち、作者が
著作権その他の許諾できる権利を持つものにだけ適用する。それ以外には適用しない。

データを再利用するときは、houritsu（<https://github.com/Kohei-Wada/houritsu>）をクレジット
してもらえるとありがたい。許諾が要らない利用では、これはお願いであり、義務ではない。

無保証：これは法的助言ではない。内容が古い、または誤っている可能性がある。依拠する前に
e-Gov か官報で確認すること。
